## Likely critical path and useful ordering

1. **Make the population measurable before repairing examples.** Capture machine-readable pre-change inventories and identities: all manifest containment relationships; generated alias address→destination relationships; data/table references and other discovered executable entries. Separate **unresolved dispatch**, **resolved-but-wrong-body alias**, and **hidden entry / over-wide owner** findings. The existing [table checker](<scripts/check-table-targets.py>) correctly measures traps, not alias misdispatch; do not silently redefine that census. Include entries that already resolve or already have their own manifest record, not just missing addresses.
2. **Establish a qualified structural witness using the existing analyzer.** Reuse [Analyzer](<scripts/check-stack-depth.py#L278-L478>) rather than creating another CFG walker. For each candidate, compare its independent entry evidence and own executable body with the container's own reachable instruction boundaries. Record actual containment, dispatch mapping, reference sites/types, owner exits, candidate exits, and uncertainty. A candidate body bound must be established by control flow and bytes, not by blindly trusting the same database end under test.
3. **Measure the whole candidate population; then choose the gateable subset.** The promising discriminator is owner reachability: the prior census found only two reachable-from-container candidates, both inside bogus `gap_prologue` database containers. Reproduce that measurement on the current 116, separating manifest and database-only ownership. Independently inspect representative failures and false positives before making reachability an invariant. Give every scanned candidate an explicit classification; retain weaker evidence as measured candidates rather than suppressing it.
4. **Repair confirmed defects in evidence-backed batches.** First prove the representative `0x7DAE0` / `0x1FF90` / `0x91C00` cases, then similar exposed defects and useful boot-path candidates. Keep legitimate owner switch arms/shared epilogues intact. Derive cleanup from the candidate's own CFG or explicitly label it inferred; do not copy a neighboring RET immediate. Regenerate affected output using `python -X utf8 scripts/relift-selected.py boundaries` and/or `python -X utf8 scripts/recover-functions.py`, plus affected derived artifacts as needed. Verify dispatch, declarations, definitions, stubs and manual exclusions remain consistent.
5. **Integrate and validate the actual durable tree.** If a narrow, independently supported invariant survives the controls and census, wire its real failure mode into `just check` and CTest after genuine findings are repaired. Otherwise deliver the deterministic classifier/report and its tests, with a precise reason the unresolved class is not gateable. Do not manufacture a green gate through a suppression baseline. Preserve the existing stack gate's **`d == 0`** invariant; the general `N + d` form is not this turn's proposed gate.
6. **Use runtime exposure to continue, not to replace static detection.** Once a stable build exists, use bounded exploratory runs with recorded settings/ledger IDs and coverage-focused observation. Seek the repaired thunk's entry and ABI-verified return, its actual tail target and the earliest subsequent stop. Same-binary repeated runs are more informative than merely lengthening a non-exercising run. If the region remains unexercised, inspect where runs diverge and add observation, not semantic forcing. Follow newly exposed critical-path stops when useful; one repaired function is not an automatic stopping point.

## Structural cautions and competing explanations

- **Real hidden entry versus legitimate label:** `0x80BD0` is a standalone SEH function with zero rel32 callers and a `.rdata` reference. Caller absence is never a negative identity test. Conversely, a switch target or shared epilogue may legitimately be inside its owner. Independent function/dispatch evidence plus qualified owner reachability must distinguish them; a reachable address can also have a dual-entry/shared-body contract, so reachability alone is not a universal veto on independence.
- **Unreachable versus unmodelled:** the analyzer's `walk` returns exits/falloffs/truncated/depths. A missing address in `depths` is not proof of non-reachability when indirect edges, table bounds or walk limits leave coverage incomplete. A present key is not sufficient either: it is recorded before successful instruction decode. Extend/expose reusable coverage and path evidence where necessary; preserve UNKNOWN, and distinguish unknown stack depth from incomplete control-flow coverage.
- **Padding/data versus execution:** a clean linear decode can cross a tail jump, padding and a new prologue and falsely attribute another body's RET to the owner. Require valid reachable instruction boundaries and check whether the owner path crosses padding or an epilogue/prologue boundary. Raw dwords, alignment and prologue patterns are discovery hints, not proofs. Alignment/padding noise filters should be measured without losing real unaligned callback immediates or relative targets.
- **Wrong alias shim versus valid folded label:** all 134 recorded shims redirect to another address, but that fact alone does not establish 134 defects. Determine whether the alias has independent function identity and whether dispatch runs the appropriate body; do not count every differing destination as wrong.
- **Database defect versus guest/runtime defect:** `tail_jump_alias` overruns and bogus `gap_prologue` owners are established risks. Repairs can stay game-local unless evidence genuinely requires a toolkit fix. Static validity does not prove runtime exposure; runtime nondeterminism, blocked transition work and remaining missing entries remain live explanations for the disclaimer hold. Do not assume an independent present-path bug or clear transition state to get past it.

## Useful parallel work and Advisor leverage

- **Detector/measurement stream:** Orchestrator or worker owns analyzer reuse, candidate report and test integration. Keep production classification independent of representative-address test fixtures.
- **Independent evidence stream:** a read-only worker checks real representative defects, negative controls and a diverse sample of newly classified candidates against original bytes/reference sites. No second CFG implementation; independently inspect the shared analyzer's witnesses. This stream can challenge both false positives and missing candidate sources.
- **Runtime stream:** archive g05/g06 coverage, profile and provenance comparison can proceed in parallel. Run the game only against a stable binary/source identity, not while generated bodies are being rewritten; avoid resource-heavy parallel builds/runs. Keep concurrent file ownership disjoint.
- **Advisor input would help** after the first census exposes ambiguous classifications: what minimum evidence makes hidden-entry separation gateable despite SEH, shared tails, dual entries or unresolved indirect edges? Also useful for alias-body equivalence, analyzer coverage/jump-table assumptions, and thunk cleanup if multiple possible vtables emerge. For runtime divergence, provide the smallest matched-run comparison and ask for the cheapest distinguishing observation. Advice is leverage, never permission; reproduced evidence decides.

## Useful completion criteria

A strong result is a maintained repository-wide detector/report with explicit coverage limits, representative bad→good and adversarial negative controls, mechanically reconciled populations, and evidence-backed repairs with generated output synchronized. A proven narrow class has an actual failing gate; an ambiguous class has transparent measured classification, not a fabricated gate. `just check` and the full final-tree CTest suite are green.

Secondary success is an exercised ABI-verified return through the repaired thunk and an honestly classified next stop, followed further when useful. If nondeterminism still prevents exposure, state **NOT EXERCISED** with measured divergence and the next discriminating experiment; this is not confirmation. No title or M15 claim without milestone evidence.

### Question and evidentiary boundary
For this exact original XBE, *under the current trapped VP implementation that always returns `0x80`*, is every feasible **direct** `PIO_FREE` gate in the frozen 28-site set guaranteed to have an unsigned compare demand at most the stub's available value (`0x80 >> 2 = 32` for variable polls, and `0x80 & ~3 = 128` for masked constant polls)? Or is a reachable demand above the applicable value witnessed, or is a bound unprovable? Here “feasible” means supported by a concrete path/input witness or a sound bound over all paths from established entries; an isolated unconstrained register value is **not** a witness. This is a question about the title **against this stub**, not a hardware capacity, unit/bit encoding, queue, read/write ordering, or proof the device works. The guest census constrains possible hardware interpretations but **does not count as either independent secondary source**; xemu-derived `0x80` is an explicit *negative control*, never support. The five hardware leaves (units/encoding, capacity, drain/completion, overflow/backpressure, ordering) remain `UNKNOWN` regardless of this answer; no source becomes true by repeating `0x80`.

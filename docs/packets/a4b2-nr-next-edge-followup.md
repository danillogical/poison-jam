## A4b2-NR-next-edge-followup — discover GP load epochs before slicing the named doorbell

### Sketch
- Discovery, not acceptance: determine the second P-image's load provenance and stable epochs, then attempt the named-doorbell input-dependence slice only on covered bytes.
- Blocker: `A4b2-NR-next-edge-r1` → `O-INCONCLUSIVE`; the bootstrap decode supplied wrong upper P words for almost all executed PCs.
- Unknowns: loader trigger/source/extent, image-I transient writes, quiescence/overlays, callers and guards of the unchanged doorbell instructions.
- Experiment: existing-log GPRST exclusion first; GP-only complete P-write watch and epoch reconstruction second; feasible PC-indexed slice last, gated on byte stability.
- Rows: concrete refutation → real VP + B3 resolution; two valid legs → `A4b2-r8`; missing proof/unstable uncovered bytes → targeted epoch/slice followup.

### Question
For the pinned first `B+0x810` GP doorbell (`seq=198852 va=803C0810 observed=3 payload=0 dsp_addr=000800`), can load events and epoch-stable P bytes support a **full feasible callers/guards/reaching-definitions slice** that excludes both VP-produced MIXBUF values and placeholder `0xFFFFB3` values from the named output/trigger, or is there a concrete feasible dependence? Phase 1 is a hard gate on phase 2; this is exploratory knowledge, never a strict criterion.

### Withdrawn / forbidden (binding ruling)
- **W1–W4:** `bootstrap_state_decode.txt`/`.json` (formerly `full_decode.*`) are valid **bootstrap-state records only**, **not** slice bytes above `0x172`; predecessor CFG edge set/reachability numbers are **not claims about the executed program** (method, both tooling fixes and single-entry interrupt/vector undercoverage stand); seven Q2 *tasks* survive, their “over all 3881 words” single-image scope/input bytes are void (`docs/reviews/a4b2-nr-next-edge-q2-preparation.md` header); withdraw “one 3881-word program”: **≥2 images/epochs** pending loader proof.
- **F1–F3:** never cite byte-identical `P 0004 62F400`, `0007 0BF080`, `00B9 57E100`, `00DB 220E00`, `00E8 0A7092` as **path-independence**: transient changes and later-image callers/guards/input dependence remain open; **instruction survival ≠ path survival**. Never slice directly from the at-exchange snapshot (continuous overlays can make even it wrong for earlier execution). Never fudge a single-image slice if PRAM never quiesces: covered per-epoch slice or `O-INCONCLUSIVE` with reason. No frozen-packet premise-change/revision event applies to the predecessor or `A4b2-r7`; `A4b2-r7` remains `R2-EXPL-INPUT`.

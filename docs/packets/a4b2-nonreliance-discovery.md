**Class:** discovery   **Contract revision:** `A4b2-NR-r2`   **Status:** draft
**Starts from:** `A4b2-r7` → `R2-EXPL-INPUT` (`docs/reviews/a4b2-r7-execution-evidence.md:95-117,165-177`); binding direction `docs/reviews/a4b2-r7-expl-input-ruling.md:19-70`.
**Baseline:** game `a000662aef3bb4d7088f3fa367d19e7ce7c157df`; toolkit `3a3c7c1fa9461d6a9cc7279180aacaaaf979ab7d`; XBE SHA-256 `FD19055756719893C466302809B433B785ECF5732DF0441286F3F605F0F3EF9C`. Verify identities and preserve unrelated edits; changed premise → stop for Planner.

### Question
Are the `B+0x810` GP DMA doorbell write's payload, address and executed-path write guards independent of **both** VP-produced MIXBUF samples and placeholder `0xFFFFB3` reads? The observed 26 MIXBUF bins and 1017 peripheral reads are real inputs, not uninitialised-buffer evidence. Output is a two-leg **discovery finding**, never a strict `A4b2` verdict.

### Experiments
1. **Diagnostic toolkit hook, owned here (not `A4b1`):** in `src/apu/dsp/interp/dsp_cpu.c` replace only GP DSP X-memory *returned* sample values at `0x1400..0x17ff` **and** alias `0x0c00..0x0fff`, after memory lookup and before the existing input-accounting hook; in `src/apu/dsp/dsp.c` replace only GP `read_peripheral(0xFFFFB3)`'s returned 24-bit value before its input-accounting hook. Do not mutate storage, VP mixing, DMA output, CPU memory, EP reads or any non-target peripheral. Gate by exact, cached `RECOMP_APU_GP_INPUT_PERTURB=<mode>:<seed>` with absent/unrecognised value a no-op (reject bad mode rather than silently running a control); allowed modes `zero`, `max` (`0xFFFFFF`), `prng` (fixed documented 24-bit deterministic stream, seed recorded), and `bad-output` (control only). A unified GP-side counter/rolling fingerprint records **both** actual returned samples and originals, with class-specific total counts, changed counts and first/last substituted values; snapshot it at the first GP_CLEAR or at run end with complete uncapped summary, not first-N logging. `bad-output` leaves inputs unchanged and, solely for this diagnostic control, uses a private copy of the GP DMA *source* with the dword covering `B+0x810` changed from zero to nonzero **at the existing watched write choke point**; never edit the original DMA buffer or guest RAM directly. Log the targeted `guest_va`, `dsp_addr`, byte offset and old/new payload. No production value changes when the variable is absent. Follow `apu_watch_trace_enabled()`'s read-once gate; test absent mode against the baseline and extend the existing `jsrf_apu_watch_fixture_test` host with selector assertions (including alias, GP-only, both-class counts/values and rejected mode) before runs; its cached env gate requires separate processes for absent, zero, max, prng and invalid modes. Add only those CTest arms needed to invoke these process-isolated controls, and retain the existing trace-on/off arms. `bad-output` must suppress `GP_CLEAR` or alter the deciding payload, else the comparator/control is invalid. **Bounded toolkit write scope:** `src/apu/dsp/interp/dsp_cpu.c`, `src/apu/dsp/dsp.c`, `src/apu/dsp/gp_ep.c`, `src/apu/apu_watch.c`, `src/apu/apu_watch.h` (only diagnostic selectors, counters, prototypes, bootstrap decode call and source-copy control), `tests/apu_watch_fixture_test.c` (only selector-control assertions). **Bounded game write scope:** `CMakeLists.txt` (only new process-isolated CTest registrations for that existing fixture target); no other toolkit or game source. Remove the `bad-output` arm at closure; leave any other diagnostic arm compiled inert when env absent or remove it. Record patch and hashes.
2. **Leg 1, image mechanism:** from `game/default.xbe`, extract exactly `I[i]=LE32(file[0x1A7D60+4i]) & 0xFFFFFF` for `0≤i<0x173`, compare all words to the archived `[GPBOOT]` block (one-offset-shift negative control). Use the *existing* DSP56300 `disasm_instruction()`/`OpcodeEntry` decoder and interpreter instruction semantics in `dsp_cpu.c` as the oracle; since its output is currently compiled out, expose a **diagnostic, env-gated decode of these 371 loaded P words to artifact text** in the already-scoped `dsp_cpu.c`, called immediately after GP bootstrap from already-scoped `gp_ep.c` (including variable-length extension words; undecodable words are gaps, never NOPs). Decode by DSP **word PC**, not x86 `inspect-jsrf.py disasm`. Enumerate all direct/indirect DMA-register setup and transfer writes in this image, resolve X/Y/P memory and DMA scratch/FIFO callback routes through `dsp.c`, `dsp_dma.c`, `gp_ep.c`; bind candidate(s) to the observed `dsp_addr=0x800`, guest `va=0x803C0810`, source payload zero at the first GP clear. `I[5]=0x000800` is a lead, not proof of the binding. For each candidate's executed path, supply a PC-indexed CFG/def-use slice: every write guard and the definitions of destination, transfer length, payload and guard flags; explicitly propagate both input classes through registers, memory, DMA and branch conditions (including loops), distinguish *read* from *relied on*. Compare trace/decode against the executed PCs and memory/DMA accesses using env-gated **uncapped event trace until first clear** where static decoding alone cannot resolve an indirect edge; archive its completeness/terminal marker, not a capped `[GPRUN]` sample. Classify `L1=PROVEN` only if **every** feasible executed-path write and guard is covered and neither input can influence them; `L1=REFUTED` on a concrete reachable input-derived influence on payload/address/guard (not merely a read or syntactically connected but infeasible path); else `L1=INCONCLUSIVE` (unresolved register-indirect/computed/table-driven branch, dynamic code/self-modification, unbound write, incomplete trace or unknown semantics). Searching opcode text/direct literals alone cannot enumerate those cases (§6.1; `A4p` precedent). Do not treat an indirect edge's absence in one trace as a proof of all feasible edges.
3. **Leg 2, comparative guest runs (Session owns build/runs):** build once and ctest, then from game root run `python -X utf8 scripts\run-jsrf.py --seconds 30 --profile exploratory --label <unique-mode-seed>` for baseline (variable absent), `zero:0`, `max:0`, `prng:1`, `prng:2`, and `bad-output:0`. Set `RECOMP_GPU_ACK=0`, `RECOMP_APU_TRAP=1`, `RECOMP_APU_TRACE=1`, `RECOMP_KERNEL_LOG_BUDGET=100000`; unset synthetic completion/bypass names from run-profiles; keep the same executable/XBE, saved-root fixture and all non-mode environment settings, 30-second bounds, guest path/bootstrap image and CPU anchor. Archive under `logs/runs/`; `check-run-profile.py`, `result.json`, image/boot records, uncapped GP counts, input-hook at-clear summary and `GP_CLEAR`/`GP_NONZERO_OVER`/`GP_ZERO_OVER_OTHER` latches establish provenance. Require frames advancing (`gp_frames≥1`, `gp_insns>0`) and **both classes actually consumed before the exchange in every comparison run**, nonzero counts/changed counts where a selected vector differs from the baseline, and different consumed-value fingerprints across zero/max/prng seeds; if baseline happens to match one vector, require comparison against at least one other changed vector. Do not equate seed selection with actual consumption. All four input perturbation runs must show the same first clear tuple `(va=803C0810, observed=3, payload=0, dsp_addr=000800)` and source-transfer context; require identical anchor/boot image and deterministic prefix through the exchange, or classify divergent context UNKNOWN rather than an input effect. `L2=REFUTED` only when controls and matched context hold but a changed consumed input causes a different tuple/no exchange within a common matched frame horizon (use the shortest complete pre-crash comparison window, not `seq`, which changes with read volume); `L2=INCONCLUSIVE` if control, changed-consumption, reachability, context or evidence integrity fails; otherwise `L2=INVARIANT` (not a general proof by sampling). The `bad-output` control must demonstrably change the latch/payload without touching the two stub inputs, and independently the target selectors' fixture plus live changed counters/fingerprints must establish input-hook activity; failure of either is INCONCLUSIVE, never invariance. **Log reconstruction:** parse write-once latch records as whole tagged records and key by class/fields, not adjacent physical lines; reconstruct each `[GPIN]` block by stripping *all* injected `[TAG]` records **including their newline**, bounding each block at its next `[GPIN]` header (including `summary`) and each field at its own key/expected array length, rejecting non-GPIN trailing text before comparison. Do not use a hand-written foreign-tag list, over-capture past `summary`, or let final `flags` swallow crash text (§7 of r7 evidence). Missing/truncated/ambiguous records → INCONCLUSIVE.
4. **Parallel register-identification thread:** inspect Xbox/MCPX primary hardware documentation for `0xFFFFB3`; if absent, seek two independent, differently-provenanced secondary sources (at least one Xbox/MCPX or demonstrably same interface), capture exact URL/version/commit/line and what read semantics they assert. Toolkit comments and guest polls are leads, **not** independent hardware sources. Record `IDENTIFIED` / `UNRESOLVED` / `CONTRADICTORY` separately from L1/L2; reserved-zero requires a qualifying source, not the current placeholder. Do **not** add a `0xFFFFB3` model in this discovery.

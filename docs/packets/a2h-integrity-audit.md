# A2h-integrity-audit-r1 — discovery, read-only accepted-row evidence audit
**Question:** Which accepted A2h decision rows rest on guest-memory reads from runs whose dumps fail the integrity gate? This packet audits evidence, not mechanism, runtime correctness, or a new trace.
**Authority/scope:** Advisor `docs/reviews/a2h-callback-slot-identity-advisor-ruling.md:18-22`; inspect only accepted A2h rows; read-only archived artifacts, plan, packets, reviews, original XBE and code; no game runs, build, tests, instrumentation, source edits, or other-line audit.
**Inventory gate:** Enumerate every A2h packet/revision and selected decision-row label in `plan-jsrf-bare-minimum.md`, all `docs/reviews/a2h-*-acceptance-*.md` (including stage-two and records), and `docs/packets/a2h-*.md`; reconcile packet/revision/row against final ACCEPT decisions, deduplicate repeated plan history, include accepted `O-OPEN`/`UNKNOWN`, and list excluded unaccepted/superseded rows with reasons. Missing or contradictory identity is `A-IDENTITY`, never silently dropped.
**Per-row ledger:** For each accepted selected row quote the exact affirmative decision claim (if any) and its decisive input/artifact location; classify EACH decision input as `log/trace/code-static`, `guest-memory-from-dump`, `live hook reads` (timestamp plus run), or `inference` (explicit premises); record mixed provenance separately rather than assigning a blanket row label.
**Run binding:** Resolve each guest-memory input to its exact archived run directory and dump, corroborate the row-to-run link in primary packet/review/log metadata, then invoke `python -X utf8 scripts/check-dump-mapping.py <that-run-dir>` separately for EACH run actually used; record exact gate status/output reference; absent/ambiguous run or unavailable gate yields `A-IDENTITY`/`A-OPEN`, never CLEAN.
**Integrity ordering:** Gate XBE-backed dump content before interpreting it; a `CONTENT_MISMATCH` makes the run's guest-memory values uninterpretable, including apparent pointer/register-derived guest values; do not repair a shifted dump, infer a passing status from another run, or replace a missing primary result with a quotation.
**Extraction controls:** EVERY extraction (row/label parse, log/trace, static disassembly/source, live-hook value, dump read and mapping status) names an independent known-answer witness in the same artifact/tool/representation, states its expected and observed value, and rejects/marks UNKNOWN an absent or failed control; preserve byte order, address width, time and provenance.
**Worked dump control:** For `inspect-jsrf.py memory`, compare known `djv000_0.adx` at `0x001D5078`: memory-order bytes `64 6A 76 30 30 30 5F 30 2E 61 64 78` must print little-endian DWORD VALUES `30766A64 305F3030 7864612E`; first also gate that specific run, then decode target reads as DWORD values, not printed memory-order bytes.
**Other controls:** Use a named accepted-row label and matching final acceptance text for inventory extraction; named fixed XBE instruction/source literal for code extraction; a known checkpoint/line and timestamp from the SAME log/trace or hook stream for those extractions; for mapping output verify the checker's documented `0x00011000` `.text` prefix `8b512c85d28b4130c70190431c00741c` against the reported comparison, recording any failed witness as UNKNOWN.
**Label-only rule:** An accepted `O-OPEN`/`UNKNOWN` asserts nothing positive: verify only final row label, revision and acceptance identity, report `ASSERTS-NOTHING`; do not backfill positive claims from narrative as though the row accepted them.
**Verdicts:** `TAINTED` iff a positive accepted row actually consumes guest-memory input from a specifically checked failing run; `CLEAN` iff positive inputs include dump guest memory and all implicated runs have passing per-run gates and extraction controls; `NO-GUEST-MEMORY` iff positive inputs are independently supported without dump guest memory; `ASSERTS-NOTHING` for verified open/unknown labels; identity/control gaps use audit row `A-IDENTITY` or `A-OPEN`, not an invented clean verdict.
**Output:** Produce a cited table `packet/revision → accepted row/claim → exact decision inputs/artifact locations → source per input → exact run(s)/timestamp(s) → per-run mapping command/status and control → verdict`; append a flagged remediation list naming each tainted positive row, exact consumed input, run, status and affected claim; report gaps and excluded rows explicitly.
**Audit rows/next action:** `A-IDENTITY` = inventory, accepted row, input-to-run link, or run identity cannot be established → resolve identity first; `A-OPEN` = other evidence/control gap → obtain missing witness; these take priority over closure even if a taint is already flagged. Otherwise `A-TAINTED` = one or more positive rows consume failing-run guest memory → name them and request remediation packet; `A-CLEAN` = complete reconciled inventory with none → permit a separately scoped caller-trace packet, not a claim it already works.
**Census caveat:** The 23/24 census is ONLY a population statement and MUST NOT be cited for any specific accepted row; per-row primary `check-dump-mapping.py` results for its exact run(s) are required, even if a run appears in the census.
**Stop/successor:** Stop at unresolved identity or control failure and report the exact edge; any `A-TAINTED` requires a separate remediation decision before dependent trace; only after this audited inventory may a distinct caller-trace packet use mapping-clean register inputs, XBE bytes and log lines; no concurrent trace.
**Safety/write boundary:** Audit executor writes only its separate evidence/review record as subsequently authorized, never this frozen packet or source; no synthetic completion, APU-trap/`0x80` suppression, fake allocation, arena widening, NULL-call bypass, guest-error edit or generated-code edit; leave `RaiseException(0xE0424943, EXCEPTION_NONCONTINUABLE, ...)` unchanged; do not touch `PIO_FREE`, `A4b2-r7`, `A4b2-r8`, `A4b1-r4`, `0xFFFFB3`, or reopen the retired NULL line or cite a DR record.

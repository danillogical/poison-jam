# A2h-rdata-call-target — discover the ADX-data indirect-call provenance
**Class:** discovery (§5.8); **revision:** r1; **status:** DRAFT for Session validation/freeze; knowledge only, no repair or strict acceptance. **Authority:** `docs/reviews/a2h-null-line-closure.md:12-26` (especially ruling 2); predecessor row/validity idiom `docs/packets/a2h-slot-within-run-attribution.md:7-33`; `docs/agent-workflow.md` §§5.8,6.1.6.
**Question:** Why does the guest perform an indirect call targeting `0x001D5078`, a `.rdata` address containing `"djv000_0.adx"`? Identify the call instruction, pointer-bearing object/field, writer and path from the filename to that field; distinguish an observed dataflow from a conjectured cause.
**Baseline/limits:** Session re-pins original XBE, game/generated source, toolkit, executable and archived evidence identities before use. The Session characterised this terminal in 3/10 same-build ON realizations; two have identical `eax=001D5078 ecx=007BFFBC edx=00000293 esp=007BFF9C`; `ecx` is guest-stack-address evidence, not proof of an object layout. The bytes/section establish a data target, not its origin or a function boundary.
**Static-first step 1:** From original XBE executable section and generated source, locate unresolved-call *dispatch/caller* by preserved return/caller evidence and recompiler `loc_` labels; decode its containing instructions from established entry/labels, NEVER byte-scan from an inferred code boundary or disassemble ASCII at `0x001D5078` as code. If caller/alignment is unproved, `O-OPEN` before any live witness.
**Static-first step 2:** XBE raw-byte search suggests **59 repetitions** of pointer value `0x001D5078` at stride 8 in a candidate `.rdata` table beginning guest `0x001D4BD4`; this is a LEAD, neither validated table boundary nor proof all entries are distinct or callable. Validate start/end, 59-entry finite universe, entry width and both field meanings from section mapping, nearby data, `loc_`-anchored original-XBE table-indexing code and generated expressions; identify index computation and whether entries hold names, functions or mixed struct fields. Boundary/index mismatch remains `O-OPEN`, never reinterpret raw-scan alignment as authority.
**Static-first step 3:** At the identified `call eax` (or prove actual operand), back-slice last `eax` definition through registers, table index, memory, stack and branches; show original-XBE instruction VAs/bytes and matching generated `loc_` labels/expressions. Confirm actual call site and target load rather than equating terminal `eax` with an immediate load; normalize addresses to `uint32`, never infer completeness from one generated-text spelling.
**Static-first step 4:** Bound the object from `ecx=0x007BFFBC`, `esp=0x007BFF9C` (`ecx-esp=0x20`) and verified ABI; establish argument slot, producer/consumer, field offset, lifetime and every feasible reaching write. Trace original `.rdata` table/name references, copies and assignments into that field; decide whether `"djv000_0.adx"` reaches a code-target field or a misinterpreted name field. Prove unique chain or name first unclosed edge; frame locality and deterministic registers are leads, not causes.
**Validity/coverage:** Offline inputs are identity-pinned XBE bytes, section map, generated-source/dispatch correspondence, original instruction and `loc_`-anchored CFG, register/stack call ABI and all feasible reaching definitions. Missing boundaries, indirect writers, conflicting paths, unverifiable archived caller or stale identities fail closed; generated-source grep is only a lead. Preserve complete terminal site/target/thread/register identity of each archived realization, not a convenient first/last event; sibling events cannot satisfy this terminal's row.
**Gap-only instrumentation:** NONE pre-authorized. Only after recording a specific static gap may Session propose a separate, bounded observation-only scope at a non-generated caller/object seam: capture one first matching terminal witness (caller/return, `eax/ecx/esp`, field address/value, producer identity) with an event-owned write-once record and uncapped counts keyed to source-derived finite classes; fixture positive/negative and overflow/loss gates, OFF structural control, same-build bounded strict ON capture, off by default at closure. If no safe lossless seam or bounded universe is shown, select `O-OPEN`, not an invented absence claim; no DR record or NULL-line instrumentation may be a row input.
| Priority / row | Predicate (offline first; corroborating run only if justified) | Next packet |
|---|---|---|
| `O-IDENTITY` | XBE/source/exe/artifact mismatch, unsafe or contradictory terminal identity/profile | Re-pin provenance; no mechanism claim. |
| `NON-TARGET` | Terminal is not uniquely the unresolved `0x001D5078` call | Preserve full site/target/thread as contrast; no attribution row. |
| `O-DATA-AS-CALL` | Unique labelled call and complete reaching-definition chain identifies filename-pointer field, writer, and erroneous call interpretation; independent XBE/generated agreement | Narrow change packet for the proved mechanism, separately reviewed; no change here. |
| `O-ALTERNATE-PATH` | Unique labelled call but verified distinct feasible field/writer paths or mismatch between expected and observed target | Next discovery packet for the named branch/definition; no majority inference. |
| `O-OPEN` | Missing caller, object ABI, reaching definition, witness completeness, ambiguous order or any other gap | Smallest named static edge or separately scoped observation-only witness packet; no negative attribution. |
**Row rule:** `O-IDENTITY` precedes all; event-first classification precedes mechanism. A positive row needs an actual terminal witness and complete, cross-checked static path (or a justified lossless gap witness); silence, capped logs, sampled history and another run's coverage never prove absence. Per-realization findings precede any across-run generalization; disagreement leaves general cause UNKNOWN. Archived frequency 3/10 is descriptive, not a promise of recurrence or a license to retry until target.
**Scope:** Only unresolved `0x001D5078`; float-bit `0x3E800000` and `0x41200000` remain contrastive, with per-terminal classification before any family claim. Retired NULL rows stand, its read path is dead, canonical-write channel uncertifiable, producer parked; never reopen them or cite DR records. No `PIO_FREE`, `A4b2-r7`, `A4b2-r8`, `A4b1-r4`, `0xFFFFB3` work.
**Prohibitions:** Observation only; no synthetic completion: never suppress the APU trap or `0x80`, fake allocation, widen arena, bypass the NULL call or edit guest error handling. No generated-code edits; `RaiseException(0xE0424943, EXCEPTION_NONCONTINUABLE, ...)` unchanged. Original assets/saves and unrelated edits remain untouched.
**Closure:** Session archives offline XBE disassembly/bytes, labelled CFG and generated-source extracts, definition/object-field proof or named gap, identity/hash index and selected row; if separately approved instrumentation is needed, archive OFF/ON raw artifacts, profile and lossless witness validation, then remove/disable gate. Reviewer checks artifacts exist, match procedure and select row (§5.8), never a strict criterion; post-review evidence edits reopen affected decision.
**Planner §5.8 self-review:** A broken call, empty source search, unexercised branch, stale build, sampled loss or non-target cannot select `O-DATA-AS-CALL`; each validity gate prevents an otherwise false provenance claim. `ADEQUATE` as a static-first discovery design, pending Session's literal source/identity validation; the actual caller, ABI/field and writer are explicitly UNKNOWN until measured, and a missing safe seam is `O-OPEN`, not grounds to reactivate the retired instrument.

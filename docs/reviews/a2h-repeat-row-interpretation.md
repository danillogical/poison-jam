# Planner ruling — A2h repeat frozen-row interpretation (revised on positive-control failure)

**Final row: `O-COVERAGE` → `A2h-slot-write-coverage-provenance`; supersedes this file's earlier `O-READ-PATH` ruling (commit `1b0a7b8`).** This is a frozen-contract interpretation revised after `docs/reviews/a2h-dr0-positive-control-failure.md` established a previously missed failure of the native DR positive control. The original ruling mistook the software `install_ok=1` comparison and DR7 arming/readback for proof that the write watch fired. They are not that proof. No source, instrument or game execution is authorized by this interpretation.

**Decisive gate:** The predecessor packet requires the *known install store* to cause an actual native DR0 write record **in addition to** the software install latch (`docs/packets/a2h-slot-read-path-displacement.md:27`). The inherited r2 packet explicitly says a missing canonical install trap selects `O-COVERAGE`, **never** no-write (`docs/packets/a2h-slot-within-run-attribution.md:19,25`). The known store at guest `0x001C4064` ran after the watch was armed on the same thread at the watched address, yet the record has zero DR hits. A programmed/read-back DR7 plus an `install_ok=1` software value check is *not* a trapped install. The DR half of the three-leg read-path test cannot be independently certified, so the repeat packet's `O-READ-PATH` condition (“only if all three legs independently certify it”) is not met. This is a **positive-control failure**, not merely shared silence. `O-COVERAGE` takes priority irrespective of K.

**What remains established:** The 28-alias page-protection census, its zero touches, the terminal mapping checks, the generated zero target and the hook's independently observed zero remain supported on the reported evidence. The 17 recorded arms and DR7 readbacks establish programming and reconciliation of arm records, **not detection of canonical writes**. K=3 establishes that three independent TARGET realizations repeat the terminal triple and the measured install-value and alias-census facts. It does **not** establish a certified writer row, no-write claim, causal read-path discrepancy, or general writer attribution. Canonical writes, writer, and mechanism remain `UNKNOWN`. `O-READ-PATH` cannot be retained by narrowing “complete continuous no-zero-write coverage” to aliases only: the frozen predicate includes canonical DR coverage and the trapped-install gate, which a retrospective interpretation cannot delete.

**Intended wording and correction:** “Complete continuous no-zero-write coverage” was intended as *positively certified coverage of the specified canonical and alias writer-observation surfaces, within which no zero-write was observed*, not a universal claim that no write happened. The wording is genuinely ambiguous and should prospectively specify both that bounded observational meaning **and** that a DR write channel is certified only after its known install write produces the required native hit; no hit from an unfired watch certifies nothing. Clarify that the third read-path leg reconciles DR event/coverage and mapping, with a post-hit value conditional on a hit, **but the independent known install-hit positive control is unconditional**. The earlier conditional-post-hit interpretation did not waive that control.

**Next evidence / reachability:** The smallest missing edge is a correctly classified, published native DR0 `#DB` from the known post-arm install write, with address, thread, write-control and DR ownership independently checked; then re-establish continuous per-thread coverage, alias/mapping reconciliation and all three legs on new qualifying TARGETs under an explicitly authorized, frozen successor. This is plausibly testable because the install store is a built-in positive control, but the current evidence cannot determine whether the problem is exception delivery, debugger handling or instrument recording; a second-chance/swallowed-event explanation is a hypothesis, not a finding. If the DR watch cannot be made to fire, report it as nonfunctional and propose an expressly revised instrument/packet or limit the result to the alias and software-read observations. **Do not silently drop the DR requirement while claiming the frozen `O-READ-PATH` row.** No sixth run, repair, or broader pivot is authorized here.

**General lesson:** Absence of records is not absence of events. Even positive arming/readback and multiple matching runs do not certify a detector that misses its own known positive control; keep independently observed values, protected aliases, canonical-write detection and causal attribution separate.

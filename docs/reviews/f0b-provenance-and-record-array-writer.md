### The question

`just check` was red on `check-generation-provenance.py --check` with two independent
problems, and the gate has no "annotated drift" state: any input-hash change or any
baseline mismatch is a hard problem. Is re-recording admissible, or does it launder the
signal the gate exists to preserve?

### Measured before the consult

- **Problem 1 is pre-existing.** Restoring the pre-patch `recomp_types.h` and re-running
  the checker removed problem 2 and left problem 1. `config/recovered-functions.json`
  changed once after the manifest was written, in `ec650f9`, which edited a single

  23:10) and it was never re-recorded.
- **Problem 2 was this session's, and owner-directed.** `scripts/patch-generated.py`
  applied 1 of 9 patches (`a4b-watch-declaration`, ledger L38): four lines in

- **`evidence` does not reach generated output.** `scripts/recover-functions.py`,
  `relift-selected.py` and `gen-abi-deltas.py` contain 0 reads of it;
  `tools/recomp/lifter.py` contains 0, and `translator.py` never reads it as a dict key.
  Measured directly: translating 41 config entries (including the changed entry

- **`--write` would have made three false claims.** `build_manifest()` re-measures

### RULING

Re-record both drifts, but as a **targeted amendment** to the existing manifest and
baseline. Do **not** run `check-generation-provenance.py --write`. The amendment changes
only the two drifted hashes, adds a top-level `amendments` list with one entry per drift
(date, path, old→new hash, cause, evidence, and the sentence *"amended, not regenerated:
generators, command and lifter identity are those of the 2026-09-29 pass"*), corrects
`generation_mode` to the `2a349c8` pass plus the T18 patches, and adds a dated
2026-09-30 entry to the baseline's `updates`. Afterwards `--check`, `--check-only` and
`tests/test_generation_provenance.py` must pass.

**Why not stay red until V2:** a gate that stayed red for 73 commits already carries no
signal, and leaving it red would hide any *new* drift before V2.

## Finding: why the gate went unnoticed

`tests/test_generation_provenance.py` is **not registered in CTest** — `CMakeLists.txt`
names no such target, and `ctest -N` lists 28 tests without it. `just test` therefore
cannot catch a provenance failure; only a bare `just check` can. The Advisor's
"uncertain" item is resolved: the test exists and passes, but nothing runs it in the
build/test loop. Recorded as a follow-up lead, not fixed here.

## Finding: `recover-functions.py` cannot complete a from-nothing rebuild

`scripts/recover-functions.py` aborts at `0x000BCF40`:

```text
RuntimeError: Incomplete translation at 000BCF40
```

**Cause (measured).** The configured span is `0x000BCF40..0x000BD8D0`, but that
function's real `ret` is at `0x000BD8B0`; the span runs 0x20 bytes past it into padding
that decodes as `aaa` (`0x000BD8C0`), which the lifter cannot translate and reports as
`/* TODO: aaa */` via `_unimplemented` (`tools/recomp/lifter.py:3291`).

**Effect.** The live `src/recomp/recovered/recovered.c` is unaffected — it was generated
before that check existed and its `body_000BCF40` contains 0 TODO markers. What breaks is
a rebuild from nothing, which `AGENTS.md` "Rebuilding the lifted code" already records as
never having been done end to end. This is the first concrete blocker found for it.
